# Provenance and third-party boundary

This revision was independently authored for `travel-roadbook-builder`. No substantial expressive source code, prose, examples, or assets were copied from `618034128/Travel-Planning-Skill`. Functional overlap is limited to public provider URLs, required parameter names, and commonplace travel-workflow concepts.

During design review, the public project `618034128/Travel-Planning-Skill` was examined for high-level interaction ideas such as compact intake confirmation, map-link fallback, query-only transport handoff, and localized revision. Those ideas were re-specified for this skill and implemented from new tests and official provider documentation. No file from that project is bundled here.

The route-link helper uses only public URL formats documented by Google Maps, Amap, and Baidu. It contains no provider SDK, API key, copied dataset, or third-party package.

Before adding any external dependency, code, template, image, font, or dataset:

1. record its name, source URL, version or revision, license, and retrieval date;
2. confirm that the intended redistribution and commercial use are permitted;
3. retain copyright and license notices when required;
4. avoid copying when the license is missing or incompatible;
5. prefer official documentation and an independent implementation for simple protocols.

For destination media, also record the creator or owner, source URL, license basis, and whether redistribution in a shareable or printable artifact is permitted. A map provider, search result, booking page, or social post is not a blanket license to reuse its images or data.

For time-sensitive itinerary facts, retain the source URL, check date, applicable trip date, and confidence status in the structured plan. That evidence establishes factual provenance; it does not transfer rights to reproduce the source's text or visuals.
