## 执行链

1. 检查实际 MCP 工具是否可调用。无工具时检查服务配置；报告具体是未注册、未启动还是需要重新加载，不能把缺工具写成无笔记。
2. 读取并执行 `xhs-login` 的登录检查，调用 `check_login_status`。未登录时通过 `get_login_qrcode` 展示二维码，让用户在小红书 App 扫码；不得索取密码或输出 Cookie。
3. 读取 `xhs-search`，按实际 schema 调用 `search_feeds`。餐饮结合近期与收藏排序，路况优先最新；记录真实返回的 ID/token，缺失数据记未知。
4. 读取 `xhs-explore`，用搜索返回的 ID/token 调用 `get_feed_detail` 获取全文及必要评论。实际 schema 优先于子 Skill 可能过时的参数示例。
5. 将来源、实际到访时间、独立性、营销迹象和读取深度写入同一个行程模型，再按 `xiaohongshu-travel-and-food.md` 分级推荐。
6. 服务或登录不通时明确报告连接问题；网页降级的结果单独标识，不能声称已完成站内搜索。

旅行研究仅调用登录、搜索与读取工具；忽略上游子 Skill 中可选的点赞、收藏和评论推广入口。不要展示原始 xsec_token 或登录 Cookie；保留在必要的调用上下文中，分享路书仅包含可用的公开引用链接。

### 会话与错误处理

- 连续请求复用同一浏览器上下文，读取结束保存更新后的登录信息；不要为每次搜索另启一套浏览器。
- 用户扫码成功是独立事实。登录检测失败、页面结构不兼容和平台设备限制应分别报告，不得都解释成用户没有登录。
- 明确出现“电脑设备登录超限”时停止重复搜索和生成二维码；保留已有凭证并定位限制。需要用户再次验证时解释原因，不承诺再次扫码一定恢复。
- 新搜索页通过真实笔记链接提取结果；不可见互动量保持未知。新页面暂不支持可靠筛选时明确报错，取消筛选后逐篇检查发布时间、收藏量和评论，不声称过滤已生效。
- 若本轮原生工具列表尚未刷新，可使用已配置本地服务的标准 MCP HTTP 入口调用同名只读工具；先核对 tools/list schema，不把 Skill 文件存在视为服务成功，也不绕过平台登录或验证。
